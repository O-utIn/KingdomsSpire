# Web 首次进入性能说明

本项目的 Web 首进卡顿主要来自三部分：动态图片串行加载、未使用的引擎模块，以及未设置长期缓存。

## 已应用的优化

- `AssetLoader.ts` 对动态 `SpriteFrame` 请求做全局去重，并支持批量并行加载。
- 主菜单、选角、初始奖励、地图会在当前页稳定后预热下一场景及其首屏图片。
- 地图页不再为每个地图节点逐个等待同一种图标；所有唯一图片一次并行加载。
- 战斗页先并行准备背景、玩家立绘和遗物图标，再创建完整 UI。
- Web 构建裁掉项目未使用的动画、Spine、DragonBones、2D 物理、粒子、视频、WebView、瓦片地图和性能面板模块。
- 长背景音乐使用 DOM Audio 流式模式，避免首次进入时完整解码大 MP3。
- 构建开启 MD5 文件指纹；仓库提供 Netlify `_headers` 示例，可让带指纹的 `assets`、`src` 和 `cocos-js` 文件使用一年不可变缓存。

## 重新构建与部署

1. 使用 Cocos Creator 3.8.8 打开项目，等待新脚本完成导入。
2. 在构建面板选择 `web-desktop`，确认 `MD5 Cache` 仍为开启状态。
3. 完整重新构建，不要把旧构建目录与新产物混合。
4. 若部署到 Netlify，将 `build-templates/web-desktop/_headers` 复制到构建输出根目录，再上传整个 Web 构建目录；其他托管平台请设置等效缓存头。
5. 首次验证时打开浏览器开发者工具的 Network 面板；普通验证不要勾选 `Disable cache`，否则无法验证二次进入和再次访问的缓存收益。

## 后续资源建议

源资源中仍有多张 1.5 百万像素、2–3.3 MB 的 PNG，且多数敌人图最终只显示在约 100–400 像素区域。下一步可在确认画质后，将敌人立绘按实际最大显示尺寸降采样，并给 Web 平台设置 WebP/PNG 压缩预设。这会继续降低首次战斗的下载和图片解码时间。

DOM Audio 在部分 iOS 浏览器上不能调节音量。如果 iOS 音量控制比首屏速度更重要，可把 `锈鼓残梦 (1).mp3` 的 Load Mode 改回 Web Audio，并先把音频压到更低码率。
